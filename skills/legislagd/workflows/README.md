# Workflows para LegislaGD

Processos padrão de desenvolvimento.

## New Feature (new-feature.md)

1. Identificar domínio (SAPL, SIGI, e-Cidade, etc)
2. Abrir issue descrevendo feature
3. Criar branch feature/descricao
4. Implementar com testes
5. PR com impacto legislativo
6. Review arquitetura + testes
7. Merge

## Bug Fix (bug-fix.md)

1. Abrir issue com reprodução
2. Criar branch fix/descricao
3. Implementar fix + testes
4. PR com causa raiz e solução
5. Review e merge prioritário

## Integration Change (integration-change.md)

1. Discussão arquitetural em issue
2. Proposta com impacto análise
3. Prototipo se necessário
4. Revisão cross-team
5. Documentação de integração
6. Implementation

## Architecture Change (architecture-change.md)

1. ADR (Architecture Decision Record) em issue
2. Proposição detalhada
3. Prototipo com métricas
4. Discussão com sertaodigital-core se necessário
5. Aprovação
6. Implementação faseada

## Documentation Update (documentation-update.md)

1. Identifique o documento
2. Verifique master (Drive vs GitHub)
3. Atualize na fonte apropriada
4. Se GitHub: PR com validação
5. Se Drive: Procedure institucional
6. Sincronize Markdown se necessário
