## Processo de Decisão

### Decisão Estratégica

1. Discussão em reunião
2. Documentação em Google Drive
3. Assinatura/aprovação
4. Comunicação para stakeholders
5. Implementação técnica em GitHub

### Decisão Técnica

1. Issue no GitHub
2. Discussão em PR
3. Code review
4. Merge em main
5. Atualização de documentação

### Decisão de Conhecimento

1. Proposta em issue
2. Criação de Skill ou atualização de manifesto
3. PR com contexto
4. Review por proprietários da Skill
5. Merge e publicação

## Autoridade de Fontes

1. Documentos oficiais (Google Drive, assinados)
2. Documentação funcional oficial (Google Drive)
3. Documentação técnica (GitHub)
4. Manifestos SDKA
5. Inferência

## Relacionamento Drive/GitHub

- Drive é **master** para estratégia e funcional
- GitHub é **master** para técnico
- Markdown exportado une ambas (sem ser master)
- **Nunca edite uma cópia derivada como se fosse master**

## Versionamento

- Documentação técnica segue Semantic Versioning
- Mudanças de breaking são comunicadas
- CHANGELOG.md registra histórico
- Retrocompatibilidade quando possível

## Conformidade

- LGPD (Lei Geral de Proteção de Dados)
- Segurança de dados sensíveis
- Princípios de software livre
- Transparência e auditabilidade
